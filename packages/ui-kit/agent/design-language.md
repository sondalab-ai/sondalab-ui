# Sondalab Design Language — Family-Resemblance Spec

> **What this file is:** the family-resemblance rules that sit *above* the token contract — the shared grammar of layout, graphic motifs, type treatment, and editorial voice that makes every Sondalab surface (spexr, introspect, daos, future products) read as one package. Where `design-system-spec.md` is the machine contract (the canonical `--sl-*`/terminal values and their generators), this file is the human contract (how to *use* those values so products look related without looking identical).
> **Audience:** engineers and designers building or migrating any Sondalab UI surface; reviewers checking cross-product coherence.
> **Owner:** marcellobarile.
> **Companion files:** `design-system-spec.md` (token contract — the values this language spends), `design-system-plan.md` (token pipeline build sequence), the identity board artifact `https://claude.ai/code/artifact/abbebb7f-5778-4af6-a9b4-2b3f169ae20f` (visual thesis). The per-product application of this language is tracked in a separate implementation plan (writing-plans), not here.

## Legend (status vocabulary)

- **Shipped / Delivered** — merged to the surface's production codebase, available to users.
- **PoC implemented (not delivered)** — built as a prototype, not merged/released.
- **Placeholder (not delivered)** — stub or scaffold only.

At authoring time (2026-08-22): spexr consumes the token architecture (delivered); introspect has adopted the shared type (delivered, type-only); daos landing and the sondalab-ui showcase are **not delivered** (this language spec is design only until the pass-1 plan lands).

## Why this exists

Colour and type harmonisation alone (phase 2 tokens) does not make products feel like one suite. introspect after its type swap still "looks the same" because the values converged but the *grammar* did not: the same accent and font can carry two unrelated layouts. This document codifies the grammar — the reusable editorial decisions — so a new product (or a reviewer) can achieve family resemblance without re-deriving it.

The reference implementation is **daos landing** (`daos/docs/daos-landing.html`): it already expresses the intended editorial modernism (hairline structure, mono structural labels, oversized display type, inversion bands, real content over marketing copy). This spec extracts daos's vocabulary and generalises it; daos is the *source*, not the first target.

## Decision 1 — Theme selector policy (two tiers)

Products reach Sondalab colour through one of two blessed patterns. This was previously decided twice, inconsistently (spexr uses `data-sl-theme`; introspect and daos use `[data-theme]`); it is now a policy keyed on substrate, not an ad-hoc per-product call.

- **Tier A — full theme adoption.** Set `data-sl-theme="light|dark|high-contrast"` on the root and consume the generated theme layer (`themes/*.css`) wholesale. Best for greenfield surfaces and chrome-heavy hosts that need every neutral. A product other than the default also loads `themes/products.css` and sets `data-sl-product="<id>"` on the element that carries `data-sl-theme` (or an ancestor of it), one product per theme subtree, so its neutrals take its own hue (Decision 2); without it the page gets the default product's amber-tinted neutrals. **Adopters:** spexr (its Theia chrome needs the full neutral set; see `spexr-theme-contribution.ts`); daos, since 2026-09-30 (its landing dropped its own colour layer and loads the kit's themes from the CDN — https://github.com/sondalab-ai/daos/pull/2); roboemot, since 2026-10-18 (its operator web UI on the robot serves a vendored, hash-pinned copy of the kit, offline, with `data-sl-product="roboemot"`).
- **Tier B — shared-root adoption.** Vendor only the shared `:root` layer of the token CSS (`--sl-*` type/space/radius/motion/etc., theme-independent). The product keeps its own `[data-theme]` colour layer, but **every colour value in that layer must resolve to a Sondalab value** (a product token equals an `--sl-*` value, an accent-registry value, or one of the product's own generated neutrals; no free-floating hex). A Tier-B product copies its neutrals from `neutrals.json` → `products.<id>.<theme>.<role>`, never from another product's entry, and sets the three light-theme numbers the kit keeps on `:root[data-sl-theme="light"]` (`--sl-accent-text-lmax`, `--slc-edge-accent-lmax`, and since 0.31 `--slc-glow`; recipe in the ui-kit README; `--slc-edge-accent-top`, the primary's lit top line, went with the line in 0.32 and nothing reads it), and on its dark layer the number the kit keeps in its dark and high-contrast theme files, `--sl-accent-band-text-lmax` (the accent inside an inversion band, capped; without it a seam or accent text in a dark band falls under 3:1). Best for surfaces with an existing editorial palette. **Adopter:** introspect.

**Why not one tier:** the generated theme layer is scoped `[data-sl-theme]`; a product on `[data-theme]` can never match that selector, so forcing Tier A on introspect would mean rewriting their working colour layers for no visual gain. Tier B keeps their selector and pins their *values*.

**Compliance test (both tiers):** open the surface, sample any surface/text/accent colour, and confirm it equals a value in `sondalab.tokens.json`, the accent registry below, or the product's entry in `neutrals.json`. Tier is an implementation detail; value-equality is the invariant. `sl-audit --product <id>` allows the default product's neutrals for everyone and a product's own tinted neutrals only for that product.

**Migration note (the loser):** Tier B is the default for products with a pre-existing palette. A Tier-B product should migrate to Tier A only if it later drops its own colour layer entirely. daos did so on 2026-09-30; introspect has not. No forced migration.

## Decision 2 — Product accent registry

Shared grammar, per-product accent. The brand default is amber (with a teal *depth* companion); each product may override the accent hue only. Everything else (type, spacing, motion, the neutral ladder) is shared.

**Neutrals are tinted per product (since ui-kit 0.29, Lumen).** The ground and the text are not a fixed grey: each role is one rung of a shared lightness/chroma ladder (`sondalab.tokens.json` → `neutrals.ladder`, oklch `[L, C]` per role per theme, chroma at most 0.014), and the hue is the product's own accent hue — so amber reads warm, indigo cool, teal green-grey, one temperature per product. The generator bakes the result to **literal hex** (Monaco, xterm, Electron and the audit all need hex; a runtime `oklch(from …)` would not reach them): the default product's into `themes/{light,dark}.css`, every registered product's into `themes/products.css` (under `[data-sl-product]`) and `neutrals.json`. The registry below is therefore an input to generated output: changing a product's accent re-tints its neutrals and is a token change. The build fails when a rung leaves sRGB, when a baked neutral would read as a hue (chroma ≥ 0.04, the ink effect's `isChromatic` threshold), and when two products with different hues bake identical neutrals; the closest pair, spexr and local-agents (indigo h 273 / blue h 260), differs by at most 2–3 per channel, which the build reports. The roles: `bg-canvas`, `bg-surface`, `bg-surface-raised`, `bg-tile` (a raised selection), `bg-sunken` (a field's fill), `text-primary/secondary/muted`, `code-fg`, `code-comment` (and `code-null`, which is comment); the borders, and the light theme's overlay, are the product's own primary text at the theme's alphas, and `border-lit` is a white highlight edge. A grey accent (oklch chroma below 0.002) has no hue to give, so its neutrals are untinted. Paper ink sits at the Lumen target's oklch L 0.20 (since ui-kit 0.35; 0.23 until then). The glass glint mirrors its lightness about 1.17 (`1.17 − l`; 1.2 until 0.35), which keeps the paper glint at L 0.97 as before; a darker tinted ink, or the old mirror, asks for a near-white sRGB cannot hold, and the build fails on it. High contrast keeps its literal neutrals.

**Fill and text are one accent, two readings.** `--slc-accent` is the colour a control *fills* with. `--slc-accent-text` is the same hue as text or a thin line: `oklch(from var(--slc-accent) min(l, var(--sl-accent-text-lmax, 1)) c h)`. The light theme sets the cap to `0.46` (0.5 until 0.29: on the darker Lumen canvas introspect's teal text read 4.49:1 on its own 12% wash at 0.47, measured from Chrome's pixels), so every registered accent's text clears 4.5:1 on its own product's light grounds and on its own 12% wash; dark and high contrast set none, and there the text is the accent. Chrome clips an out-of-gamut relative colour per channel rather than reducing its chroma, so the derived text leans toward red: amber at the cap paints `#933A00` (oklch hue 45, the fill's is 66) where a gamut-mapping browser would paint `#7E4A00`. Both readings are held to 4.5:1 by `palette-contrast.test.mjs`. The label on a fill (`--sl-text-on-accent`) is derived on light too: white below oklch L 0.59, near-black above — whichever pole reads better. The near-black is oklch L 0.16, the same dark pole as every other labelled fill in the kit (`--slc-on-accent-fill`, `--slc-on-<status>`): one rule, written once (`--_sl-on` and its threshold `--_sl-pole-l`, generated into `tokens.css`), since 0.32.1. The pole was 0.22 and the threshold 0.61 until then; 0.16 lifts the worst dark label across the registry from 5.03 to 5.64:1, and 0.59 is where it and white read about equal for the registered hues (0.61 left spexr's bare `#5b6cff` white at 4.17:1 where the dark pole reads 4.65). **Hover and press** (0.32.1) take the danger tone's step, size included: 0.05 of oklch lightness hovered and 0.10 pressed, **toward black**, the way a key reads pressed — **unless the label is the dark pole and would read under 5.4:1 on the fill pressed toward black**; then the fill steps toward white. 5.4 is a rule, not a tuning: a pressed primary must leave its label 4.5:1 on a glass pane too, and a pane over a dark page shows a tenth of that page through the fill, which costs a dark label up to about 0.9:1. The direction is decided once per fill, on the press, so hover and press always move the same way; each state moves at least ΔE 4.5 (OKLab × 100) from the last, and the edge and the foot are the state's own fill in shade. Among the registered fills only introspect's teal on paper and local-agents' blue on ink step toward white; amber, daos, introspect's mint, both dangers and every white label step toward black. The step runs along the line to the pole it moves toward, so it never leaves sRGB: darkening keeps chroma in proportion to lightness, lightening eases it. One macro (`--_sl-step-hover` / `-press`, with `--_sl-hold` and the fill's luminance `--_sl-lum`) serves the theme's steps, the accent fill, the danger tone and the role-var fallbacks. 0.32.0 mixed 89% / 76% toward black on paper (introspect's teal pressed to 3.15:1) and lightened the dark hover; stepping always away from the label (an earlier cut of 0.32.1) turned the dark labels' presses pale enough to read as disabled. **A fill that carries a label** (0.32): where neither pole reaches 4.5:1 on the accent itself (white on spexr's `#5b6cff` is 4.17), the product registers a `fill` and the role `--slc-accent-fill` carries it (generated into `products.css` for a Tier A host since 0.35, copied from `neutrals.json` → `products.<id>.fill` by a Tier B layer), and every accent fill that carries a label — the primary, a checked check, radio or switch, a count badge — takes it with its label (`--slc-on-accent-fill`, the pole that contrasts with that fill), its hover and press (the kit's one step, on every theme) and its edge (`--slc-edge-accent`, the fill in shade). Unset, each of those is the accent's own, exactly as before; high contrast owns its accent and resets it. The fill is the accent's, never a second accent: links, tags, the ring and selection stay on `--slc-accent`. The theme supplies only a *number*, never a second colour, so a product that overrides only its accent (Tier A) or maps only `--slc-accent` (Tier B) gets its own hue in all three roles. Inside an inversion band the ground is the page's ink, so the band re-derives the text with the theme's `--sl-accent-band-text-lmax` cap (dark, high contrast) **and a fixed floor of oklch L 0.68** (all themes): on light the orange read uncapped, but spexr's indigo measured 3.54:1 and introspect's teal 4.22 on the band (2026-10-01). Status inks used as text or a thin mark in a band (badge, callout tick, progress bar) take the same floor and cap through `--slc-<status>-text`; the band also re-derives the accent wash, because high contrast's (and spexr's registered) subtle is opaque and would put a mark of the wrong ground under the text.

Rule: a product picks **one** accent hue and derives hover/active/subtle from it; it never introduces a second chromatic accent. **Derivation is concrete and complete:** the generator emits **every** accent step as a hue-relative expression off `--sl-accent-default`, so a product override that sets **only the hue** re-derives the whole family (the one-var contract — no step is a bare literal that could leak the previous hue). Two forms: `color-mix()` off `--sl-accent-default` for steps a straight mix reproduces (hover everywhere, subtle everywhere, light/HC active), and CSS **relative colour** — `oklch(from var(--sl-accent-default) calc(l * k) calc(c * s) h)` — for a step whose hand-tune a mix can't reach while preserving hue (dark-active, whose value carries a slight chroma/hue shift; `color-mix` in sRGB would leave it fixed and off-hue for other products). The relative-colour step also emits a preceding baked-literal declaration as a graceful fallback for browsers below the relative-colour floor (Safari 16.4 / Chrome 119 / Firefox 128); `color-mix` itself is Baseline. The audit enforces this mechanically as of ui-kit v0.7.0 (`auditAccentDerivation`, an R-level `accent-derivation` finding): a bare-literal accent step is a defect unless it is a graceful fallback (redeclared with a relative-colour expression in the same block) or a step registered in the product's `accent-registry.json` entry — the "register instead of derive" path for a fixed-hue product whose steps don't fit the shared ratios (see `packages/ui-kit/agent/HANDOFF.md`). Semantic status colours (ok/warn/err) are separate from the accent and shared — but the `--sl-status-*` tokens are tuned for **on-canvas** use. On an inverted surface (a block whose background is the strongest neutral, e.g. an ink-on-paper output panel) they lose contrast; there, derive an on-ink status pair locally rather than using the canvas tokens (daos `.artifact .ok`/`.no` are a correct instance of this — kept as light-on-ink greens/reds, not swapped to the darker canvas tokens).

**The spectrum is not an accent** (Prism, since ui-kit 0.21). The light theme also carries a six-hue spectrum (`--sl-spectrum-*`, Decision 3). It is shared — identical in every product, never re-hued to a product's accent — it exists in the light theme only, and it never carries state or meaning: selected, focused, checked, busy and the primary action stay the accent's; a spectrum stop standing in for state is a defect. **Since ui-kit 0.28 the kit paints no edge, rim or arc with it** (owner, 2026-10-02: "drop rainbow from fields and everything else"). On the light theme, as on dark, an edge follows the accent or its context: a filled control (the primary) is outlined in its own fill in shade (`--slc-edge-accent`), a neutral control in the one control edge (`--slc-edge-control`), a card or surface in its own ground in shade (`--slc-edge-surface`), and the aurora, the press light, glitch and the run light are the accent's and its depth companion's. The spectrum survives only where a consumer asks for it by name: `sl-haze`, `sl-spectral` and a halftone's `data-sl-ink="spectral"`. A rainbow edge that the author did not opt into is a defect.

## Decision 3 — Data-viz & code palettes

Three shared palettes that are **not** brand accents and must never track the product hue: a categorical data-viz ramp, a syntax-highlight set and the light theme's spectrum. The first two were per-product literals until they recurred across ≥2 products (spexr + introspect), which is the New-token-policy threshold for promotion.

- **`--sl-viz-0..7`** — a categorical ramp of eight distinct hues for arbitrary series / one-colour-per-item (an agent-monitoring wall, per-event-kind tinting). Emitted **per theme** at the lightness each theme's grounds need (the no-theme default on `:root` is the dark ramp); the consumer places the hues on its own surface. It is independent of `--sl-accent-*` and carries no semantic meaning — for *semantic* state (error, warning) use `--sl-status-*`, not a viz slot. Every slot clears 3:1 on every ground of every product; the Lumen canvas (0.29) took the light teal and orange below it, so they moved a step darker at the same hue: viz-2 `#0E958A` → `#0E9186`, viz-3 `#D26A00` → `#CD6400` (worst ground now 3.12:1 for both, from 2.98 and 2.92).
- **`--sl-code-<role>`** — the syntax-highlight palette (`fg`, `comment`, `keyword`, `string`, `number`, `boolean`, `function`, `tag`, `builtin`, `null`). Canonical = the **Lumen target's** hues since ui-kit 0.35 (atom-one until then) for `keyword`, `string`, `number`, `function` and `builtin`, authored as oklch and baked to hex by the generator: a value outside sRGB keeps its lightness and hue and gives up chroma (light `function` and `builtin`), never a per-channel clip; `boolean` reads as `number` and `tag` as `keyword` (the target has no tag colour, and atom-one's sat within OKLab ΔE 1.5 of the new number on paper), so the palette is five hues. Emitted **per theme** (light + dark), and into `neutrals.json` beside each product's neutrals for a consumer that needs hex (an editor theme). High-contrast is intentionally omitted — syntax is undefined there and consumers fall back. A chromatic code token stays semantically stable and readable; it does not re-hue per product. The three neutral roles are the exception since 0.29: `fg` and `comment` are rungs of the neutral ladder (Decision 2) and `null` is `comment`, so they take the product's tint like the rest of its neutrals (`products.css`, `neutrals.json`). Every role clears 4.5:1 (comment and null 3:1) on canvas, surface, raised, tile and sunken of every product, and in an editor on raised under the current line (the primary ink at 4.5%) and under the selection (the product's accent at 18%).
- **`--sl-spectrum-0..5` / `--sl-spectrum-ink-0..4`** — Prism, **light theme only**, and **opt-in only** since 0.28. The first set is *light* — rose, orange, yellow, teal, blue, violet — for glow (`sl-haze`). The ink set is the same wheel darkened to ≥ 3:1 on the light grounds, for anything that must be *seen* as text or a dot (`sl-spectral`, a halftone with `data-sl-ink="spectral"`). Nothing in the kit applies either by default: from 0.21 to 0.27 they also painted the rims of cards, fields and the primary button and every effect's light on the light theme, and the owner dropped that on 2026-10-02. The tokens stay — a product may still spend them. Dark and high-contrast reset both to `initial`, so the ornaments fall back to nothing or plain text there; no rule branches on `[data-sl-theme]`. A Tier-B product that wants the ornaments declares the eleven values in its light layer.

**Adopters:** spexr (darkfactory categorical wall → `--sl-viz-*`; atom-one hljs → `--sl-code-*`), introspect (agent-event-kind tints → `--sl-viz-*`, with error/warning routed to `--sl-status-*`; JSON view → `--sl-code-*`). Machine values live in `sondalab.tokens.json` (`shared.viz`, `viz.{light,dark}`, `code.{light,dark}`, and the ladder's `code-fg`/`code-comment`); the audit allowlists them automatically because they ship in `tokens.css` / `themes/*.css` (and, for a product's tinted code neutrals, its `neutrals.json` entry).

## The family-resemblance layer

Each rule below carries a **compliance level per substrate** (see the matrix). Layout rules are expressed as **invariants** (a spacing scale, a rule weight, a measure, a type-scale relationship) — never as fixed templates — so a data-grid app with hard pixel columns can satisfy them as readily as a marketing page.

### L1 — Type treatment

Rewritten for Lumen in ui-kit 0.30 (owner, 2026-10-02: Geist and Geist Mono for the UI, Fraunces for the brand only, controls in sentence case, the mono uppercase register shrunk to micro labels). Before 0.30 the roles were Fraunces / Instrument Sans / Martian Mono and every structural label, badge, tag, chip and segmented item was mono uppercase tracked 0.14–0.22em.

- **Five roles, fixed pairing.** UI = `--sl-font-sans` (Geist): body, controls, labels you read with a control. Display = `--sl-font-display` (Geist too, kept as its own role): headings and the oversized anchor. Mono = `--sl-font-mono` (Geist Mono): identifiers, figures, tags, chips (0.36), counts, meta and micro labels. Brand = `--sl-font-brand` (Fraunces): the wordmark and the monogram, and nothing else — a heading, a title or a numeral set in Fraunces is a defect. Pixel = `--sl-font-pixel` (Geist Pixel Square, 0.39): the display accent, below. There is no serif anywhere in the UI. The kit ships all of them (`@sondalab/ui-kit/fonts.css`: variable, latin-subset woff2 with their OFL licences); a surface that loads them another way names the same families. A surface may substitute the *mono* face for a narrower one where fixed pixel grids demand it — an `adapt`, not a violation, provided the substitute stays monospace and the sans/display roles are unchanged. (introspect keeps IBM Plex Mono for its `ch`-clamped columns, a substitution made against Martian Mono's 0.7em advance; Geist Mono's is 0.6em, the same as Plex, so introspect's rollout may retire it.) A product's code editor and terminal keep their coding mono (`--sl-font-code`; spexr keeps JetBrains Mono): that is product content, not the kit's mono role.
- **Controls speak in sentence case.** Anything you operate, and the words read with it — buttons, fields and their labels, selects, chips, segmented items, tabs, nav items, breadcrumbs, badges, table heads, callout titles — is sentence case and never tracked open, and all but the chip are `--sl-font-sans`, at the control's own step (`--sl-text-sm`, or `--sl-text-xs` in dense parts; a button is Lumen's 13.5px and 12.5px small since 0.36). A chip is set in the mono since 0.36 (Lumen's composer chip): what it names is a reference or a value — a file, a status, a model — as a tag's is, and it is still a control, so sentence case and untracked. Write the label in sentence case in the markup ("Run checks", "Passed"); nothing upper-cases it for you.
- **Micro labels are mono, uppercase, lightly tracked — and only micro labels.** Eyebrows, section indices, nav group titles, stat labels, figure captions, labelled rules, a pane's meta line: `--sl-font-mono`, `text-transform: uppercase`, `--sl-text-micro` (10.5px), weight 500, `letter-spacing: 0.06em`, the muted ink. This is still the strongest family signal, and since 0.30 it is spent on *structure only*: a micro label names a region, it never names an action. Uppercase anywhere else in the kit is a defect (the lockup is lowercase pixel since 0.39 — L3). **The rule is about role, not size:** see the display-scale numeral bullet below.
- **Headings.** `--sl-font-display`, `font-weight: 600`, `text-wrap: balance`, `line-height: --sl-line-tight`, and negative tracking that tightens as the size grows: `-0.02em` for a card or empty-state title, `-0.03em` for a dialog title or an `--sl-text-2xl` heading. Sizes step off the shared scale (`--sl-text-xl`/`--sl-text-2xl`) for in-flow headings.
- **Oversized display is a structural element, used sparingly.** Hero/anchor headings scale beyond the fixed token scale via a fluid clamp (pattern: `clamp(2.7rem, 1.6rem + 5vw, 5.4rem)`), not a token — the size is fluid, so it is a documented pattern, not a `--sl-text-*` addition. Display is Geist 600 tracked `-0.045em` to `-0.06em`, tighter as it grows (`.sl-anchor`: `-0.05em`), and set solid, `line-height: 1` (owner, 2026-10-02); in-flow headings keep `--sl-line-tight` (1.2). At most one oversized anchor per screen. The kit vendors Geist upright only, so display emphasis is colour or weight, never a synthesised italic.
- **A display-scale numeral, the lockup and a single display word are set in Geist Pixel Square.** A section index, a card's folio, a step number, a stat's value, the compact lockup and one emphasised word in a heading take `--sl-font-pixel` (Geist Pixel Square, vendored in `fonts.css`) at the whole-cell sizes only: `--sl-text-px-1…4` (12.5 / 25 / 37.5 / 50px). The face draws one pixel cell per 0.08em, so a multiple of 12.5px gives 1, 2, 3 or 4px cells; any other size smears them. **Owner amendment, 2026-10-26 (direction D, picked from `lab/pixel-directions.html`):** this replaces the 2026-09-13 ruling (mono at display scale, "shape and colour, never the face", made after Fraunces at `opsz` 144 was rejected and confirmed 2026-10-02), which the pixel face now answers as the one display accent. Body and UI text stay in Geist; code stays in Geist Mono; Fraunces stays the wordmark's and the monogram's. The pixel face is **proportional** (advances at 100px: i 38, W 91, 1 49, 8 65; Geist Mono is 60 for every glyph), static (one weight, no synthesised bold) and has no `tnum`, so it is not a monospace substitute: a figure that changes in place (a counter, a timer, a column of numbers that must align) keeps `--sl-font-mono`. Set it untracked (`letter-spacing: 0`), never uppercase; the accent word is `.sl-px`. Where a numeral wants more than the face, spend it on shape and colour as before: clip the brand pair to the glyphs, cut them out of a material, outline and offset a second copy behind them.
- **Body measure.** Running text is capped at ~`63ch` (convention var `--sl-measure: 63ch`, defined locally — not a token, it is layout-level). Never let prose run full-bleed.

### L2 — Structure & spacing

- **Spacing rhythm off the scale.** All gaps/padding step off `--sl-space-*` (0.25rem base). No arbitrary spacing values in new work. **The workbench follows the grid too** (owner, 2026-10-05): ui-kit 0.34 brings the title bar, the activity bar, the tree, the status bar, the tile tab, the palette and the toast within a pixel or two of the Lumen IDE demo at 1440×900, and every gap, padding, inset and row, bar or control size is a whole number of 4px steps. Where the demo sits between two steps, the kit's own rules decide (one control height, 32px), then the demo's invariants (the activity bar's 44px pitch, 4px round a status item, 10px round the palette's field), then the 0.33 value. The tile tab and the toast live in `components.css`, so their 0.34 shape reaches every product at its upgrade, not only a workbench. **The controls follow it too** (0.36): the button, the badge, the tag, the chip, the keycap and the check box are Lumen's within a pixel or two, every gap and padding a whole number of 4px steps (a button 12px in, 8 small; a badge, a tag and a chip 8px in and 4 above and below; a keycap 4px in), and a control's row on the grid: a button 32 and 24 small, a chip 24, the small button's row it sits in. A badge and a tag are marks in a line of text, not controls; they keep the 22px they had. **Two exceptions, each pinned by its value:** the tile strip's 2px gap between tabs (0.31), and the in-button key's -2px block margin (0.31), which is its overflow into the button's line, not spacing. Radii are shape, not spacing, so Lumen's own stay off the radius scale: r7 on a tile tab and on the small button, r9 on an activity item, r8 on a count badge's pill, r12 on a toast, r5 on a check box (the keycap's corner) and r2 on a chip's dot. Type sizes are shape too: a button's 13.5 and 12.5, a tag's 11.5 and a chip's 12.5 are Lumen's, off the type scale.
- **Hairline structure.** Structural separation is a single `1px` rule in the theme's line colour — section tops, header/footer borders, card edges, gutter rulers. Weight is always `1px`; no heavy borders, no drop-shadow-as-separator (casts are reserved for what is lifted — a tile, a key — and for genuinely floating surfaces, through the depth recipes below).
- **Depth is lightness, not lines** (Lumen, ui-kit 0.31). What is nearer the viewer is lighter: canvas, then surface, then raised, then **tile** — the rungs of the neutral ladder (Decision 2). Seven recipes spend them, as role-vars in `components.css` (`--slc-depth-*`), so no product re-derives a shadow:
  - **Tile** — a selection lifted out of its pane: the tile fill, a lit top hairline (`--sl-border-lit`), a 1px ring and a short cast. A selected list row, the current nav item or page, the chosen segment and a selected table row are tiles, and so are a selected tree row and a palette's active result (0.33). **Hover never lifts:** it stays a flat wash of the ink, and only selection lifts. The tile is depth, not a state cue (its fill and ring read 1.00–1.34:1 against its ground; 1.42 before the 0.35 hairlines), so every selected or current tile carries **the seam** (L3, kit-wide since 0.33). The accent marks only an icon on a tile and the seam of a container that holds the focus — never a tile's fill or an edge. (Until 0.31 selection was the accent wash, and the nav's current item carried a 2px accent edge on its leading side.)
  - **Flat tile** — a tile that does not leave its row: lit and ringed, no cast (an active tile tab).
  - **Island** — a pane on a darker frame: lit, with the quieter ring. The workbench's panes (`.sl-pane`) and its terminal blocks spend it (0.33, `workbench.css`); the lit pane adds the light of its seam (0.34, as Lumen renders it, three roles in `components.css`): a drop that falls below the pane (`--slc-lit-drop`), and, for the product to paint on its own chrome, a wash on the tab strip or head along its top (`--slc-lit-wash`) and a tint on the row under it (`--slc-lit-tint`), each as strong as `--slc-glow` says. No accent rim round the pane (owner, 2026-10-05).
  - **Key** — a keycap (L3).
  - **Sunk** — a well, an inset cast on the sunken rung: a field, a select, a textarea, the switch's track and the segmented control's track (0.32). The check and radio boxes sit on the canvas instead (0.36, Lumen's), one well, deeper than the sunken rung on paper; in an inversion band, where the canvas is the band's ink, they keep the band's sunken wash.
  - **Float** — an overlay: three layers of cast under the overlay's own border in shade, which is the ring (a dialog).
  - **Cast** (0.34, Lumen's) — an overlay that keeps no border (the palette, the toast): the float with the ring folded in, the overlay's own fill in shade, and lit along its top (`--slc-depth-cast`). High contrast draws its ring in the theme's line; forced colours, which drop it, get a drawn outline.
  A host that wears a recipe carries no border of its own, so the lit line sits flush under the ring — a lit line one pixel below a border, with a band of fill between them, is the gap L6 forbids. Casts are black at each theme's alpha (`--sl-shadow-sm|md|lg|inset`; the pre-0.31 cool ink is gone). High contrast trades every recipe for a drawn ring (selection in the accent, a key or an island in white; no well, no cast); forced colours turn them off and selection becomes `Highlight`. The inversion band re-derives each recipe from its own washes. A theme that turns a recipe off sets it to an empty shadow (`0 0 transparent`), never `none`: a recipe joins a box-shadow list (a control's depth and its focus halo, below), and `none` voids the list.
- **The controls carry depth too** (Lumen, 0.32). Each is a rung with a part of a recipe, never a new shadow:
  - **Primary** — a flat key standing on its own base, a **foot**: one more pixel of its edge (its fill in shade) along the bottom, inside the 1px border, so the bottom reads 2px deep. It is a background layer, never a border width or padding, so the box is a plain button's and a product's own padding gives the same row height on a primary as beside it, without knowing the foot is there; and never a cast, so a consumer that strips a button to text with `background: transparent; border: 0` strips the foot with the fill. Pressed, the foot moves to the top and the key sinks by it (`translate`; the press, a 97% sink since 0.36, keeps `transform`). The lit top line it had until 0.31 is gone (the owner's Lumen default).
  - **Secondary** (`--ghost`) — a raised key: the raised rung in the one control edge, lit along its top inside the edge and standing on the short cast (the tile recipe without its ring, since the edge is the ring); hover lifts it to the tile rung with the edge's hover step. A pressed toggle sits flat.
  - **Plain** — text: no edge and no fill, at rest and under the pointer alike; it has no declared hover state of its own (none since the 0.32 keys), and under the effects layer it answers the pointer with the dither like every button. Held, it sinks like every button; as a toggle (`aria-pressed`) it takes the accent wash and ink, the one control edge and the seam (0.36.2, L3 Tile).
  - **Icon button** — clear at rest in the one control edge, the glyph in the secondary ink; hover brings the surface rung up under it. Only a chrome glyph inside a workbench primitive may drop the edge (L3).
  - **Field, select, textarea** — sunken: the sunken rung and the sunk recipe inside the one control edge. **Check, radio, switch** — the box and the track are wells too (the check and radio boxes on the canvas since 0.36, the check at r5; the switch on the sunken rung) (the track wears the sunk recipe; the switch is 2.1 × 1.25rem with a 0.85rem knob); checked, each fills with the accent fill on an inset foot of its own shade and a soft glow of the fill, as strong as `--slc-glow` says (none on high contrast or under forced colours). The fill need not find the box on its own ground (amber on paper reads 1.65:1): its edge finds it, and the tick, the dot or the knob says it is checked. **Segmented** — a sunk track in the one control edge, the chosen segment a raised tile.
  A control writes its depth into a private value the kit paints, so its focus can add the halo without dropping the depth (L6). The filled controls derive their fill set (fill, states, label, edge) on themselves, so an accent or `--slc-accent-fill` set on any subtree reaches them. Glass owns the depth of what it is on: on a glass control the foot (on a built pane), the raised cast and the well stand down for the material's own edge.
- **The danger tone** (0.32). `.sl-btn--danger` (and `.sl-icon-btn--danger`) is a tone, not a variant: it rides the variant it is on. On a primary it swaps the fill for the danger, labelled with `--slc-on-danger`, edged and footed in the danger in shade, its hover and press the kit's one step (toward black on both themes since 0.32.1: both dangers hold their label at 5.4:1 pressed); on a secondary, a plain or an icon button it is the danger ink on a 12% wash of itself with a danger edge, filling with the danger on hover. Its focus ring, the border that joins it and the halo are the danger's, as an invalid field's are. One destructive action per view, and never the only signal: say what will be lost in the label.
- **Radii** (0.31): `--sl-radius-sm` 6px (rows, tiles, small chrome), `--sl-radius-md` 8px (controls, fields, callouts; 10 before), `--sl-radius-pane` 10px (an island pane, new), `--sl-radius-lg` 14px (cards, dialogs, overlays; 16 before). A keycap is 5px, and so is a check box (0.36). Tags, badges and chips are r6, the small radius, since 0.36 (owner, 2026-10-05: they were pills).
- **Hairline grid technique.** Card grids are formed by a `1px` gap over a line-colour background (`display: grid; gap: 1px; background: <line>`), cells painting their own surface — producing crisp shared rules between cells instead of doubled borders. This is a signature; prefer it over bordered-card grids (which the house style otherwise avoids).
- **Gutter & ruler.** Content sits in a max-width wrap (`~78rem`) with a fluid gutter (`clamp(1.25rem, 5vw, 6rem)`, convention var `--sl-gutter`); on wide viewports a `1px` vertical ruler at the gutter edge is an optional editorial accent.
- **One control height.** Controls that share a row share a height: button, field, select, segmented control and icon button are all **32px** (the small button 24px, and a chip with it, 0.36), each summing a fixed line, padding and a 1px edge (the primary's foot is a background layer, so it changes none of that, 0.32). Since 0.36 a button's line is a fixed 14px whatever its type size, so Lumen's 13.5px type and a product's own size give the same row. Before 0.27.0 they measured 33.6 / 36.6 / 36.1 / 36.5 / 32px, so a field and its submit button never aligned. A product that needs a taller control scales the row, not one member of it.
- **Sections lead with an index.** A section opens with a mono `sec-idx` label (numbered where the content is genuinely a sequence — see the structure-is-information rule) beside its heading, separated from the previous section by a `1px` top rule.

### L3 — Signature components

These recurring parts carry the family look. A surface need not use all, but any it does use should match:

- **Wordmark (official logo)** — the brand is typographic, no pictorial mark. Primary: `sondalab.` set in `--sl-font-brand` (Fraunces) weight 500, `letter-spacing: -0.05em`, with the trailing period in the accent (`.dot { color: accent }`). The brand face is the wordmark's and the monogram's alone: since 0.30 `--sl-font-display` is Geist, so a wordmark set in the display role is a defect. Compact lockup (headers, tight spots): `sonda/lab`, lowercase, in `--sl-font-pixel` (Geist Pixel Square) at `--sl-text-px-1` (12.5px, 1px cells, close to the 12px it replaces; a hero lockup may step up to `--sl-text-px-2`), `letter-spacing: 0`, with the `/` (a child `b` or `.sl-lockup__sep`) in the accent ink. Owner amendment 2026-10-26 (direction D): it was Geist Mono 300, uppercase, tracked `0.2em`, with a middle dot in the accent (Martian Mono 300 before 0.30), and it keeps no uppercase and no tracking now; the class is `.sl-lockup`. `sondalab-lockup.svg` still draws the 0.30 lockup until the asset follows. Source of truth: the identity board artifact `https://claude.ai/code/artifact/abbebb7f-5778-4af6-a9b4-2b3f169ae20f`; reference implementation: `sondalab-ui/showcase/index.html` (`.brand-word` hero + `.wordmark` header).
- **Monogram (avatar)** — where the wordmark is too wide to read (social profile pictures, square tiles), the mark contracts to `s.` in the same Fraunces cut (`--sl-font-brand`) and tracking, letter in the theme's primary text colour and the period in the accent, on a full-bleed square tile of the theme's surface. Three fixed corrections, all for the small end of the scale: the mark is sized to the inscribed crop circle (~60% of the canvas wide) rather than the square; the accent period is scaled +35% around its own centre so it survives a 32px render; and it is pushed +0.06em off the letter, because the wordmark's tight tracking is drawn for a period at its natural size. Rendered assets: `packages/ui-kit/assets/sondalab-avatar-{ink,paper}.{svg,png}`.
- **Eyebrow** — the micro label above a heading: mono, uppercase, `--sl-text-micro` (10.5px), weight 500, tracked `0.06em`, muted (L1).
- **Tag / tier marker** — inline mono mark at r6 (a pill until 0.36), 11.5px, in sentence case, tracked `0.02em`: `1px` border in a soft accent tint, small dot or square glyph before the label, accent-coloured text. Used for status/classification. Mono because what it carries is an identifier ("Research tier", "v0.30"); sentence case because it is read, not shouted.
- **Inversion band** — a full-width block flipped to `text-on-*` on the strongest neutral (ink background, paper text), used to punctuate rhythm and mark the thesis or primary call-to-action. The recurring inversion is a core motif; at least one per long page is idiomatic. Every control in a band is found by the band's own control edge (0.36.1): the band's ink at the least share that clears 3:1 against the band and against the control's own wash, 48% on the light theme's dark band and 53% on a light band, read off the ink's lightness. It is written on the ink, never on `currentColor`, which a control set in a lighter ink would dilute. A button group there draws its rules from its members, since the band's surface is a wash that hides nothing. A pressed toggle keeps that edge too (0.36.2). A filled control — the primary, a checked check box, radio or switch — keeps its fill and label, but in a band its edge and foot are the fill held to the mid-tones (0.36.2), oklch L 0.55–0.59, which read 3:1 against a dark band and a light one alike, so no theme branch: on a light band a bright fill reads 1.07–2.4:1 (high contrast's yellow, a mint), and on the dark band a dark fill hovered or pressed sinks to about 2:1.
- **Sticky translucent header** — `position: sticky`, background `color-mix(paper 86%, transparent)` + `backdrop-filter: blur()`, `1px` bottom rule; the brand lockup left, micro-label meta and sentence-case controls right.
- **Real-content blocks** — where a surface shows output (JSON, terminal, code, data rows), show *actual* content in mono on the ink surface, not illustrative filler. This is both an editorial-voice rule and a visual one.
- **Keycap** (0.31) — every shortcut is a small physical key: `.sl-kbd`, Geist Mono 500, at least 20px square, radius 5px, a fill that steps from raised to surface, a ring in the default line, a lit top line and a base that is its own fill in shade (`--slc-depth-key`: a full step on paper and a quarter of one on ink since 0.36, where a full step read as a black line; Lumen's), 4px in, one cap per key. Inside a button it rides in the label as a child `<kbd class="sl-kbd" aria-hidden="true">` (18px, 16px in a small button, giving its extra height back so the 32px row holds), never as `::after`, which glass owns; the button names the shortcut with `aria-keyshortcuts`. The cap's text is the label's own colour on a fill that steps away from the label, so it never reads weaker than the label beside it.
- **Tile** (0.31) — selection is a raised tile (L2), and a selected or current tile is a tile **plus a seam** (owner, 2026-10-02, on the nav item; kit-wide since 0.33): a 2px line, half the tile's height, 3px inside its leading edge in a row or a column, or a short line 3px above its bottom edge in a tab, a segment or a page. Its ink says where the focus is: the accent as a line of light (`--slc-seam`) while its container holds the focus, the muted ink while it does not, so the selection a keyboard would act on lights up; a palette always holds the focus, and a host outside a kit container opts in with `--sl-seam-focus`. Against the tile and the ground around it the seam reads ≥ 5.24:1 on the page and ≥ 3.4 in the band; on the light theme's dark band it is floored a step above the band's accent text (oklch L 0.72 against 0.68), so a dark product hue the floor lifts out of sRGB still clears 3:1. The tile alone found the current item at ~1.0–1.3:1 against its ground, where the 2px accent edge it replaced read ≥ 5.24:1; the seam holds ≥ 3:1 against the tile on every product, theme, the band, Tier B, a lit pane and the palette. A pressed toggle — a plain, secondary or icon button with `aria-pressed` — carries the same short line (0.36.2), 1px above the bottom edge of a small button, always in the accent: it is the one thing about "on" that reads 3:1 against the button at rest (its wash and ink read 1.0–2.6:1), and the one control edge stays. A chip says "on" with its filled dot instead. It is a layer of the item's background, never a pseudo-element, because glass, press and glitch own an effect host's `::before` and the aurora its `::after`. A selected table row has none: its state is carried in its content. The IDE's tab strip is a row of flat tiles (`.sl-tabs--tile`: no underline, the active tab a flat tile in the primary ink, its icon in the accent, a dot for unsaved work). The tab's close glyph (`__close`) is **borderless chrome, the one documented exception to the one control edge**, with the activity bar's buttons (0.33): a glyph that lives inside another control would put an edge inside an edge.
- **The lit pane** (0.33, `workbench.css`; 0.34 as Lumen renders it) — a workbench is islands of light on the canvas (`.sl-pane`, the island recipe at `--sl-radius-pane`), and the pane that holds the focus is lit (`data-lit`, set where the focus is): the raised rung, a seam of the accent along its top edge as a line of light from where the corner ends, fading in from the leading edge and out before the far one, and that seam's light: a drop below the pane, a wash on the tab strip or head along its top, a tint on the row under it (L2, Island), never a rim round the pane. One lit pane per workbench, so at thumbnail size the focused pane is the bright one. The seam is the pane's `::before`, so it paints over a header or a tab strip with a ground of its own; glass, press and glitch on a pane are unsupported (they own `::before` too). A product whose layout clips the pane's shadow wears the drop inward on the element under the pane.
- **Title bar** (0.34, `workbench.css`) — the workbench's top frame on the canvas: a 44px grid whose centre track (up to 32rem) holds the command field, the product's mark (the display face, 700, with a dot of the accent) and a crumb on the left, a slot for a compact menu, a cluster of icon buttons on the right that rest on the surface rung in their own edge, one of them able to carry an unread dot. The command field is a control: the one control edge on the surface rung, lit along its top, the shared focus ring. The bar is the window's drag region; nothing in it that takes the pointer is. The product's mark is not the Sondalab wordmark, which stays the brand face's.
- **Status bar** (0.33, `workbench.css`) — the workbench's meta line sits on the canvas as the Lumen target draws it: facts in the sans at 12px, sentence case, the muted ink, each a 20px pill at r6 (0.34), and one that does something (a button, a link) brings the surface rung up under the pointer; a value read as data (a branch, a model) in the mono at the primary ink, as written, never upper-cased (a branch is case-sensitive). Hairlines between groups of facts are opt-in (0.34; Lumen draws none), an accent dot sits beside a state that is live while its words say it, and breathes (L4), and a fact that does not fit ends in an ellipsis. Its height is its own (28px), never its content's. It is never `role="status"` as a whole: a fact that must be heard gets a live region of its own.
- **Activity bar** (0.33, `workbench.css`) — the column of views on the frame: borderless chrome glyphs in the muted ink (the exception to the one control edge, with the tab's close glyph), hover a flat wash, the current view a flat tile on the surface rung with the nav item's seam and its glyph in the accent. A count on a view is a small badge on its corner (0.34, a child, so the item's pseudo-elements stay an effect's), the mono on the accent fill that carries a label, ringed in the canvas; the view's name says the count.
- **Tree** (0.33, `workbench.css`) — 24px rows at 13px (0.34), indented by their level (read from `aria-level` up to 8, a deeper row holding at 8; a flat list also says `aria-setsize` and `aria-posinset`), a twisty the size of a 12px chevron that turns with `aria-expanded`, hairline guides under each ancestor's twisty where a tree asks for them (opt-in since 0.34). Selection is a tile with the seam: raised, with its cast, an accent seam and an accent icon, while the tree holds the focus; flat, its seam and icon muted, while the focus is elsewhere.
- **Command palette** (0.33, `workbench.css`; 0.34 Lumen's) — an overlay that floats on the cast (L2) with a glowing line of the accent just inside its top edge, translucent over a blur where the browser blurs (opaque otherwise, and in high contrast), a field in the one control edge that keeps the focus and points at the active option, results whose active row is a raised tile with the accent seam, keycaps for shortcuts and a `<mark>` for a match (heavier, underlined in the accent). It never animates: it is driven at typing speed.
- **Terminal block** (0.33, `workbench.css`) — one command and its output as a small island, in the product's coding mono (stepping down to the sunken rung in a lit pane, so its fill still bounds it); its exit status is a short mark on its top edge and the exit text in the same ink: 0 the success, `cancelled` neutral (a stop the user asked for), any other code the danger, no mark for an exit not known or a command still running. A real-content block: it may sit on the ink surface of a band, where its wash goes, and it is the only workbench primitive supported there.
- **TUI patterns** (0.38) — for a command-line surface (the Term substrate): step lines, the `? [Y/n]` confirmation, the summary line, and the `NO_COLOR`, non-TTY and ASCII rules are in [`tui-patterns.md`](tui-patterns.md); the glyph and layout tokens are the `tui` section of `sondalab.tokens.json`.
- **Toast** (0.33, `components.css`; 0.34 Lumen's) — what arrives floats: the raised rung at r12 on the cast (L2), whose ring is its only edge, in a stack at the bottom right, newest nearest the corner. Its tone is a line of light on its top edge, fading from its start to the middle, and the wash under its mark; a toast that dismisses itself shows its time left as a 2px bar of the tone along its bottom; its words stay neutral. The stack is no landmark and no live region: it holds two regions side by side, a polite one for every toast and an alert one for a toast that must interrupt, and the toasts carry no role. Over a modal dialog the stack is a manual popover, shown again after the dialog opens.
- **The primary's foot and the focus halo** (0.32) — the filled action stands on its own base: a 2px bottom edge in its fill in shade, the second pixel a layer of its background so the row stays 32px whatever padding a product gives it (L2); the secondary is a raised key beside it, a field a well. Focus is the flush ring with a soft halo of its own colour around it (L4). Keys stand, tiles lift, wells sink, focus glows: one physical vocabulary across the kit, never a drop shadow used as a separator.

**Canonical recipe — eyebrow + tag** (0.30). These two are the strongest family signal, so their values are fixed here (a convention, like `--sl-measure`; not a token, because products bind them to their own local colour vars). Every implementation cites this recipe rather than re-deriving it; a product substitutes its own token names for the roles in brackets.

```css
/* eyebrow — the micro register: mono, uppercase, 10.5px, +0.06em */
.eyebrow {
  font-family: var(--sl-font-mono);          /* or the product's mono face */
  font-size: var(--sl-text-micro);           /* 10.5px; 10–11px in px-scaled UIs */
  font-weight: 500;
  letter-spacing: 0.06em;
  text-transform: uppercase;
  color: [text-muted];
}
/* tag / tier marker — accent-tinted mono mark at r6, sentence case, leading
   dot (0.36, Lumen's shape on the 4px grid: 22px tall; a pill before) */
.tag {
  display: inline-flex; align-items: center; gap: 8px;
  font-family: var(--sl-font-mono);
  font-size: 11.5px; font-weight: 500;
  letter-spacing: 0.02em;                     /* sentence case: no text-transform */
  color: [accent];
  border: 1px solid [accent-subtle];
  border-radius: 6px;
  background: [accent-subtle];
  padding: 4px 8px; line-height: 12px;
}
.tag::before { content: ""; width: 6px; height: 6px; border-radius: 50%; background: [accent]; flex: none; }
```

Current citations (they predate the 0.30 recipe, and move to it in each product's rollout — introspect at Checkpoint B, spexr in S1): introspect `.sl-eyebrow`/`.sl-tag` in `introspect/web/src/theme.css`; spexr `.spexr-agent-chat__label`, `.spexr-spec-resources__caption`, and `.spexr-df-card__status` in `packages/theia-extensions/src/browser/style/spexr.css` — these adopt the **eyebrow** half of the recipe (mono uppercase tracked, in the brand mono `--sl-font-mono`; since https://github.com/sondalab-ai/spexr-ide/pull/46 every uppercase structural label in spexr follows it). spexr has **not** adopted the tag/pill half; its existing status pills `.spexr-df-pill--attn/--error` are untouched. In spexr the label face is the brand mono `--sl-font-mono`, deliberately distinct from code: code-content runs (`.spexr-df-card__branch`/`__trail`) mirror the editor font `--theia-code-font-family`, and source-code surfaces keep the coding mono `--sl-font-code`: labels are design-layer, code content mirrors the editor.

### L4 — Motion

- **Two curves and a spring, three speeds** (0.31, Lumen; one ease before). Every state change uses `--sl-motion-ease`, `cubic-bezier(0.25, 1, 0.5, 1)` (was `cubic-bezier(0.2, 0.8, 0.2, 1)`); what *arrives* — a dialog, a tooltip, a toast — uses `--sl-motion-enter`, `cubic-bezier(0.22, 1, 0.36, 1)`, which moves at once and settles long; a control returning from a press uses `--sl-motion-spring` (below). Durations always come from `--sl-motion-fast|mid|slow`, never a literal, so reduced motion (which zeroes them) stops everything. Entrance reveals use a small rise (`translateY(~6px)` + opacity) on `--sl-motion-mid|slow`. The kit's own overlays do this since 0.27.1: a dialog rises 6px as it opens (`@starting-style`, and back as it closes where `overlay` holds it in the top layer), a tooltip 4px, and since 0.33 a toast 6px as it arrives — transitions, never keyframes, so a browser without `@starting-style` just shows them.
- **Stagger, don't fade-everything.** Where multiple related elements enter, stagger them (nth-child delays) rather than fading the whole screen at once.
- **No page-load choreography in the kit** (owner, 2026-10-02, with Lumen). The kit animates what arrives — a dialog, a tooltip, a toast — never the page itself; a page that wants an entrance stagger owns it, on the motion tokens. An ambient state may breathe while it lasts: the live badge's dot and, since 0.34, the status bar's live dot (a ring of itself that swells and fades every 2.4s, `--sl-motion-fast` × 20, on the arrival curve), each only under `prefers-reduced-motion: no-preference`, both held under `data-sl-fx-still`, and the dot stopped in a `data-sl-fx="off"` region and under forced colours.
- **Respect reduced motion.** The token layer already zeroes durations under `prefers-reduced-motion`; never re-introduce motion that bypasses the tokens.
- **Controls give under the finger.** Held, an icon button, chip, segmented or pagination item squashes a little and keeps its volume (`scale(1.02, 0.968)`); a text button sinks to 97% about its centre (`scale(0.97)`, Lumen's, 0.36), a press and not an entrance, so it is no page-load motion, and a member of a button group does not move at all, since a sunk member would open the 1px rules between its keys (L6); a switch knob stretches toward where it will travel; a check or radio box shrinks; a slider thumb grows and flattens. Tabs, nav items, list rows, fields and cards don't move — a glass-pane card only sinks a hair (a third of the swell). Glass control panes press the same way (a glass text button sinks to 97% too), and a wrapper's `--slfx-pane-swell: 1` still stands them down; since 0.36 it stands down a bare or `sl-fx-press` text button's sink under it too, which is how a button group holds its members still. Let go, it returns on `--sl-motion-spring`, whose one small overshoot is the bump (owner, 2026-09-30: "like if they are gummies" — the Quiet strength). Transitions only — never a keyframe, which would also play when a page loads with a box already checked — so reduced motion stops it with the rest.
- **The hover is a dither wipe** (owner, 2026-10-26, direction D; it replaces ink, owner 2026-10-01, reworked 2026-10-13). On a button or icon button the pointer's answer is a fill that grows through an 8x8 Bayer threshold from where it crossed the edge (~0.26s, `--sl-motion-dither-in`) and drains toward where it left (~0.32s, `--sl-motion-dither-out`). The cells are 3px squares, the kit's pixel unit; the silhouette stays smooth, because the fill is clipped to the control's own radius and the layer never draws an outline: the control's border and ring remain its edge, and a round icon button stays a circle. Entering mid-drain reverses from where the wipe is, with the new origin; nothing loops. **The dither owns its fill and its label, bound per variant from role-vars, never by theme (it lies over the glass tint, L6):** the inverse neutral on a primary (`--slc-text`), the accent on every other control (`--slc-accent-fill`, the danger on a danger tone), and once half the control is covered its label flips, with no transition, to the kit's own on-fill pole read off that fill (`--_sl-on`, 4.5:1 on every registered accent, both themes). The control's own hover colour still applies as declared. Touch raises no wipe. Tier 1 only (`mount()` builds the layer on the first pointer entry, never at mount), never under reduced motion, high contrast, forced colours or `data-sl-fx="off"`, where the declared hover stands. Until 0.39 this was ink, a pool of light under the pointer. The layer is injected on the first hover, so a button's `:empty`, `:first-child` and `:only-child` selectors change then. Its host's `position: relative; isolation: isolate` is declared at zero specificity: a consumer's own unlayered rule wins over it, and a rule in a cascade layer loses to it.
- **State is an attribute, never only a colour.** Pressed is `aria-pressed`, current `aria-current`, selected `aria-selected`, invalid `aria-invalid="true"` (a field's edge, ring and halo all turn to the danger ink together, and an `sl-field__error` line with a drawn mark says what is wrong), mixed `:indeterminate` (the DOM flag; a native checkbox never carries `aria-checked`). A state is drawn at 3:1 against the control at rest, by a mark the rest state does not draw — a seam, a chip's filled dot, a tick, a dot, a knob's travel — or by its fill; a pressed edge against the rest edge is not that comparison, since the accent and the neutral edge sit at the same lightness (0.36.2). Under `forced-colors: active` (the user's own palette, distinct from the kit's high-contrast theme) every state that was only a fill, a shadow or a gradient — a slider's value included — repaints itself in system colours (`Highlight`, `HighlightText`, `CanvasText`), and the effect layers that would paint over it are hidden.
- **Interaction, not opacity.** Hover/focus states change colour/border/background meaningfully; `hover:opacity` alone is not a state.
- **Focus is a flush ring with a soft halo** (owner-approved, Lumen, 0.32). The ring is the outline, 2px, flush on the border, and the border takes its colour (L6). Around it, a halo of the ring's own colour at ~22%, `--sl-focus-glow-width` (5px) wide, starting exactly where the ring ends, so nothing of another colour shows between them. It is composed onto the control's own depth, never instead of it and never with `!important`, and it is drawn in `--slc-focus`, so an invalid field or a danger button glows in the danger. A field shows it on any focus, a pointer's included (it is where you type). Off in high contrast and under forced colours, where it would be a page colour on `Highlight`. The halo is decoration on top of the outline: the outline alone carries the state.

### L5 — Editorial voice (copy)

- **Precise and technical, never marketing.** Name things by what they are and do. Prefer a real measured figure or executed output to an adjective.
- **Active voice; controls state their effect.** A button says what happens; its confirmation says it happened.
- **Structure encodes truth.** Numbered markers, eyebrows, dividers appear only where they reflect something real (an actual sequence, a real classification) — not as decoration.
- **English for product copy and all identifiers**, matching the suite.

### L6 — Effects & material

- **Four families, one meaning each.** Glitch means *something re-resolved* — a value changes, a destructive action is confirmed, validation fails. Aurora means *attention lives here* — focus, an active tab, a running operation, the primary call to action. Glass means *this is a physical surface*, a state rather than an event: a card edge, a field, a keycap. Goo means *these belong to one another* — it marks a set, and it answers the layout rather than the pointer. A family never fires outside the meaning it owns.
- **An effect that means nothing is switched off.** This is L5 ("structure encodes truth") applied to motion: glitch is never ambient on a control, aurora never marks something that is not currently the focus of attention, glass never animates on its own — its reflection moves, the way a mirror's does; the edge does not.
- **The reference is https://libraries.dev/, and its lesson is scale.** Everything there is one or two pixels wide, low in opacity, and fades within a few tens of pixels. Effects spend their budget on *light and shape*, never on *weight*: a structural separator stays `1px` whatever an effect is doing to it, the chrome is a hairline on the border the component already has, the aurora is a 1px arc with bloom rather than a band, and no effect rewrites a declared value, so a surface stays free to re-parametrise its own radius without touching the effect.
- **No gap between lines, in any case** (owner's ruling, 2026-10-01). Wherever two lines meet on an edge, nothing of another colour shows between them: a control's soft inner line is its edge at half strength over whatever fill is painted, so it always sits between edge and fill; a frame that a control fills gives up its border to the control's edge; the focus ring sits flush on the border (`--sl-focus-ring-offset: 0px`) and the border takes the ring's colour, a hovered, pressed or checked border included, and high contrast's drawn edge too (a state that outranks the shared focus rule hands its border back under focus, 0.32); the focus halo (L4, 0.32) starts where the ring ends. Two strokes with a band between them read as a gap, not as depth.
- **Glass is chrome on the element's own border.** A hairline exactly as wide as the border (a borderless element gets 1px), reflecting a moving environment: bright and dark bands at high contrast, the product's hue as pastel flecks between them — never as a tint over the whole ring. One soft halo wanders slowly around the edge; the ring brightens under the cursor; its environment falls faintly onto the near edge of whatever effect element stands within a few pixels of it, the way a mirror's does. Its two poles are placed around the page's own ground — on ink between the ground and the theme's brightest neutral, on paper between white and a mid grey, never black, which reads as dirt on a light page. This is what the GPU is for, and the only thing it is for; where WebGPU does not answer, the same border carries a static conic hairline that must stay correct on its own. **A glass text button is a pane** (`--pane`), whatever its variant — made of glass, not merely edged with it (since 0.32 a text button is glass only where the author puts the family on it; a bare one is a Lumen key, L2): a slab of light under the label (a glint along the top, a shade along the bottom, a 1px rim inside the edge), a glint that follows the pointer, and a hairline that turns to face the pointer fringed with the accent on one side and the depth companion on the other — dispersion, which is what refraction looks like on an edge. The label is never refracted; nothing behind the button is bent. **A glass primary's label** is the pole that reads on the pane as it composites — its resting fill at 90% over the canvas — and where that pole is white the page behind the fill is put in shade as the composite nears the poles' meeting point (from none at oklch L 0.54 to half at 0.59), so white holds 4.5:1 over a real page and not only over the fill (0.32.1; spexr's indigo on paper read 4.32:1 without it, 4.94 with it). The share, the white label and the look stay "glass, white, 90%"; on ink, and on any white-label fill already dark enough, the shade is zero. Hovered and pressed a built pane stays a pane: the step is carried by its tint, at the same share, and a pane's own paint is never an opaque fill under it (0.32.1). The one fill on a pane is the hover dither (owner, 2026-10-26, direction D): 3px cells at z-index -2, after the tint, so it paints over the frost and the tint and under the shine, the live light, the ring and the label. The first cut lay under the tint, where a glass primary's 0.9 accent tint hid it almost completely. A pane's own paint is still never an opaque fill; the dither is a dotted one, present only while the pointer is on the control. On paper the pointer's glint is colour, not white: a white glint on cream is invisible, and the reference's own light preset composites its light with multiply and saturation. (Since 0.29 "paper" is the light theme's generated canvas, a near-white tinted with the product's hue — `#eae6e2` for the default amber, the other products' in `neutrals.json`; glass stays neutral on it — the accent/depth fringe was retired on 2026-09-24, and Prism does not bring it back.) **Glass owns the depth of the control it is on** (0.32): the secondary's raised cast and a field's well stand down for the material's own edge and soft line, and so does the primary's foot where the pane is built (with no script or no `backdrop-filter` the primary is its own opaque key and keeps it); under keyboard focus the glass edge carries the kit's halo itself. High contrast and an opt-out region keep the shipped control: the kill switches take an effect host's shadow away and give the control's own depth and focus halo back (and a workbench surface its own island, 0.33, or, for a toast and a palette, its cast, 0.34), and in an opt-out region they hide the material's own layers, so a glass primary there is its opaque key, its own fill under its own label (0.32.1; the layers `mount()` built kept it a 90% tint over a blurred page until then). The aurora and the hover dither change no depth. **Pseudo-elements are the effects'** (0.33): glass, press and glitch own an effect host's `::before`, and the aurora its `::after`. A selected tile's seam is a layer of its host's background, so an effect keeps its pseudo-elements. Four marks are a `::before`: the lit pane's seam (which must paint over the pane's own children), the palette's seam (0.34, Lumen's glowing line), the toast's tick and the terminal block's exit mark, so glass, press and glitch are unsupported on a pane, a palette, a toast and a terminal block. Nothing takes `::after`. The title bar and the activity bar take no pseudo-element for their marks: the mark's dot and an activity item's count badge are children, and a title-bar button's unread dot is a layer of its background.
- **The aurora is light, and it is CSS.** The border-beam: a 1px arc riding the border — the accent's depth companion at the tails, the accent along it, on every theme (from 0.21 to 0.27 the light theme painted it in the spectrum; the owner dropped that on 2026-10-02, so light follows the accent as dark does) — with a bloom of the same light that peaks on the edge and falls away on both sides of it, outside the element as much as inside. Light is never truncated: an aurora element sits under no ancestor that clips (`overflow` other than `visible`, `contain: paint`, `clip-path`) — a scroll container wraps the table, not the card beside it, and a grid separates its cells with `gap`. Its hue drifts a little either side of the accent while it sweeps. Four readings, separated by the *fraction of the perimeter lit* and never by colour or speed: static on focus (~70%), sweep for ambient liveness (~70%, one turn per 3.2s), busy while real work runs (18%, one turn per 1.1s), determinate when the arc length *is* the value. It inhabits an edge that already exists — a second concentric ring would stack the border, the aurora and the focus `outline` into an unreadable sandwich — and where the edge is not a ring (a tab's underline, a link's, an inversion band's top rule) it is linear. A filled element has no edge to inhabit, so there the arc steps just outside the fill (`--rim`), in the accent's depth companion rather than the accent the fill is made of, and a busy filled control keeps full opacity: it is working, not unavailable.
- **The goo welds neighbours; it does not answer the pointer.** The goo states that several elements are *one substance*: a declared container owns a single silhouette layer, each marked member contributes its own rounded box to it, and members that come within a declared gap of one another grow a soft neck between them. It is laid out and welded at rest, because belonging is a property of the layout and not an event; the opt-in `sl-fx-goo--drift` lets members wander a few pixels around that layout (neighbours in opposition, never past half the weld) so a neck thins and re-forms, and reduced motion gets the static weld. Two silhouettes can only weld if they share a filter coordinate space, which is why the container owns the layer. The content is never filtered here either: the members ride crisp on top, and each silhouette is painted in its own member's fill, so where two weld their colours run into one another across the neck. A member that has welded gives up its own border *and its own background*, and the substance paints it — an outline drawn across a merged shape reads as a card stacked on a blob, and an opaque rectangular box covering a neighbour's substance reads as boxes stepped over one another rather than as drops merging; the member keeps its text. One standing alone keeps both. A member with no fill of its own contributes the field's declared substance rather than a hole in it. A **form control or a link is never a member**: it paints its own chrome through layers this family does not own, so a welded control keeps an outline the substance was meant to replace, and its own affordance is worth more than the merge. Standard elements only; where a member must be operable, an element that paints nothing of its own and carries the semantics through `role` and a tab stop. The author binds the *gap* at which two members weld — a distance readable off their own layout — never the blur behind it, and that distance is spent on dilation first: dilation preserves an outline where blur melts it, so a substance whose whole budget went into blur reads as melted rather than as a material. Members may move, and a substance that stayed where its member used to be would deny the claim the family makes. Light is not truncated and neither is a substance: the goo reaches past the outermost member, so the same no-clipping rule the aurora carries applies to the container, one scale up.
- **The aurora renders state; it never *is* the state.** A busy aurora requires the element to carry `aria-busy="true"`; a determinate one requires `role="progressbar"` with `aria-valuenow`. A screen-reader user, a reduced-motion visitor and a high-contrast visitor all get the state from the markup; the aurora is how the state looks, not where it lives.
- **The effect budget: at most one ambient aurora, one glitch burst and one deforming element, per document, at a time.** A later aurora request wins and the pre-empted element falls back to its resting edge; a later glitch burst is dropped, not queued. Busy auroras are exempt — they are bound to real work, and several can legitimately run at once.
- **Three kill switches, all hard requirements.** `prefers-reduced-motion: reduce` (nothing animates; static material survives, and the chrome stops its environment, its halo and its swell — a product with a *documented* reason may keep the glitch animating, and only the glitch, by taking the derogation explicitly), `[data-sl-theme="high-contrast"]` (every family off, the GPU field torn down), and `data-sl-fx="off"` on any element (that element and its subtree, at every tier). No effect ever replaces or removes the focus `outline`.
- **Classes are additive, colour is derived.** `.sl-fx-*` composes onto a shipped `.sl-*` class and never replaces it. Every hue is `color-mix()` over a role-var in CSS, or a token read at runtime and passed as a uniform in JavaScript and WGSL — no literal, anywhere, ever.

## Reconciling shared grammar with "one unexpected layout decision per screen"

The house aesthetic (personal `CLAUDE.md`, UI Aesthetics) requires ≥1 unexpected, intentional layout decision per screen. That does **not** conflict with this shared grammar: the grammar fixes the *materials* (type roles, spacing scale, rule weight, motifs, motion, voice), while the surprise is spent on *composition* (an asymmetric split, an oversized anchor, a full-bleed inversion, an unexpected adjacency). Family resemblance comes from shared materials; distinctiveness comes from per-screen composition. A screen that satisfies the grammar but reads as a generic centred card grid has failed the house rule; a screen that invents a new type scale or a second accent to be "surprising" has failed the grammar. Spend boldness on layout, keep the materials shared.

## New-token policy

Express the language in **existing** `--sl-*` tokens. A new token forces regenerating `packages/`, satisfying `check-drift.yml`, and bumping **both** `packages/ui-kit/package.json` and `packages/palette-py/pyproject.toml` in the same PR (see `AGENTS.md`). Therefore:

- **Kept as conventions, not tokens** (layout-level, fluid, or product-local): `--sl-measure` (~63ch), `--sl-gutter` (fluid clamp), the oversized-display clamp pattern. Products define these locally with the canonical values above.
- **Owner's override (2026-09-30):** the Prism spectrum (`--sl-spectrum-*`) was promoted on the owner's call, not on the ≥2-products rule below — it is the light theme's identity, not a value found recurring in products. Since 2026-10-02 the kit no longer paints with it by default (Decision 2); the tokens stay, because removing a token is a breaking change and a product may use them.
- **Owner's override (2026-10-02, Lumen):** `--sl-bg-tile` (a raised selection), `--sl-bg-sunken` (a field's fill) and `--sl-border-lit` (a white highlight edge) were added with the neutral ladder in 0.29, on the owner's choice of the Lumen direction rather than on the ≥2-products rule. They are neutral rungs, so they follow each product's tint like every other neutral.
- **Owner's override (2026-10-02, Lumen type):** `--sl-font-brand` (Fraunces, the wordmark and the monogram) and `--sl-text-micro` (10.5px, the micro-label register) were added in 0.30 on the owner's choice of Lumen's type, not on the ≥2-products rule: moving display to Geist left the brand face without a role, and the micro register sits below `--sl-text-xs`, which the 32px control row is built on and so cannot move.
- **Owner's override (2026-10-02, Lumen depth):** `--sl-radius-pane` (10px, an island pane), `--sl-motion-enter` (the arrival curve) and `--sl-shadow-inset` (a field's well) were added in 0.31 on the owner's choice of Lumen, not on the ≥2-products rule. The depth recipes themselves are role-vars in `components.css`, not tokens.
- **Owner's override (2026-10-02, Lumen controls):** `--sl-focus-glow-width` (5px, the focus halo's width beside `--sl-focus-ring-width` and `--sl-focus-ring-offset`) was added in 0.32 on the owner's approval of the halo, not on the ≥2-products rule. The accent fill (`--slc-accent-fill`) and the danger tone are role-vars and classes in `components.css`, not tokens.
- **Per-product neutrals are generated, never hand-copied.** A product's tinted neutrals come from the ladder and its registry hue; a Tier-A host loads `themes/products.css` and sets `data-sl-product`, a Tier-B layer or a hex-only consumer (an editor theme, a terminal, a preload page) copies from `neutrals.json` → `products.<id>`. A hand-tuned neutral in a product is a defect, not a blessed deviation.
- **A new token is justified only** for a genuine shared, fixed value that recurs across ≥2 products and cannot be a convention — and then it goes through the full regen + dual-bump flow. Realized instance: the `--sl-viz-*` / `--sl-code-*` palettes (Decision 3), promoted once spexr and introspect both needed them.
