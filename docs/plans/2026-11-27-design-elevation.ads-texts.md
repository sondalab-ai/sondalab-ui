# ads change texts for the design-elevation plan

ads targets a change started with `--text` only by its exact original text. It keeps only a hash of that text. See https://github.com/sondalab-ai/agentic-dev-system/issues/216. This file keeps each text, verbatim and on one line, so a later session can run `ads work`, `ads status`, `ads diff`, `ads ask` and `ads signoff` on the change.

## Phase 2.2 — DESIGN.md fixes 1–6 (started 2026-11-27)

Owner picked fixes 1–6 after the DESIGN.md scaffold test, and approved the layout rule draft for fix 5.

```text
Improve the generated packages/ui-kit/agent/DESIGN.md so a design agent that reads only this file builds screens with the kit instead of rebuilding it. A test agent given only DESIGN.md rebuilt every component by hand, guessed values that DESIGN.md prints as formulas, and missed the layout and pixel-face rules. Make six fixes in scripts/gen-design-md.mjs, and regenerate DESIGN.md. 1. Use the kit: add a section near the top that says how to consume @sondalab/ui-kit: the CSS files to import and their order, the data-sl-theme and data-sl-product attributes on the root, and a table of every shipped component class with what it is for, generated from packages/ui-kit/agent/catalog.json. State the rule: never rebuild a shipped component, use its class. 2. Resolved values: every value DESIGN.md prints is a final value per theme, never a formula and never a private custom property such as --_sl-on. Resolve --sl-text-on-accent for each theme from the existing derivation. Give --sl-shadow-inset and --sl-measure their real values from the sources. The generator fails if any printed value still holds var of a private property. 3. Product mark: add the rule for a product name in a header, taken from the Title bar entry of docs/design-language.md: the product name in the display face at weight 700 with a dot in the accent, and the sondalab wordmark in the brand face stays the brand alone. 4. Accent registry table: give every column a header that says what it is, and explain the labelled fill of a product such as spexr in one sentence from agent/accent-registry.json. 5. Layout: add this new rule to docs/design-language.md, in the layout part, as owner-approved on 2026-11-27, and carry it into DESIGN.md. Settings and form screens: a sidebar nav, sl-nav, beside one main pane. The pane opens with a head: eyebrow, title, one-line lede, and any scope switch on the right. Each section is one row of two columns: title and one-line description on the left, controls on the right, at most two control columns wide. Sections are split by 1px hairlines, never by cards. Pending edits collect in one action bar at the foot of the pane: a note of what changed, then Discard and the primary Save. Why: the reader scans the left column to find a setting and acts on the right, and one bar means one save for the whole page. 6. Pixel face: carry the full list from docs/design-language.md of what takes Geist Pixel Square, a section index, a card folio, a step number, a stat value, the compact lockup and one emphasised word in a heading, and its note that the rule is about role, not size, so a micro section index stays mono. Keep the existing constraints of the generator: values come from the sources at build time, the output is deterministic, and rules carry no dates or amendment history.
```
