On 2026-10-02 the owner rejected three visual directions for the Sondalab DS (A Broadsheet / editorial print, B Instrument / Linear-Raycast precision, C Poster / Bauhaus). He gave four reasons, all at once:
- not bold or premium enough;
- too print- and serif-heavy;
- wrong for a dev tool;
- components feel generic.

Earlier he called a night of correctness work "almost imperceptible from a user perspective".

**Why:** the flagship consumer is spexr, a Theia AI IDE. The DS has to look like a top-tier dev tool first (Linear, Zed, Warp, Cursor, Raycast, Vercel calibre) and a marketing site second. Correctness work (contrast, edges, sizing) doesn't register as quality to him.

**How to apply:**
- Judge visual proposals inside real product screens (an IDE shell, settings, a data view), never as component sheets.
- Lead with a contemporary sans and mono. Keep serif as a rare brand accent only. This overrides the generic "pair a display serif" preference for this DS.
- Give components named signature details.
- When he asks for quality, put the visible jump first and the invisible hardening second.
- Ground research in real products and curated galleries, with measured specifics.
